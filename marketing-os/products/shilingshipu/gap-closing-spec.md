# 落差收窄规格 v1 · 时令食谱

写给：创始人 + Codex
日期：2026-08-18
前提：**本规格作者没有看过线上站点**（沙箱代理封锁 www.shilingshipu.com）。因此每一条都写成**独立可发布、互不依赖**的改动，并标注工时。依赖未知事实的条目单独标 `⚠️需确认`。

---

## 要解决的问题

用户打开一个节气产品，感受到的是"我应该过的生活"和"我实际过的日子"之间的距离。距离产生愧疚，愧疚产生流失。

**处理落差只有两种方式：加宽（更美、更全、更理想）或收窄（更小、更真、更做得到）。目前市面上所有节气内容都在加宽。本规格全部是收窄动作。**

四层落差，三层能治：

| # | 落差 | 能否治 | 对应批次 |
|---|---|---|---|
| L1 | 说吃香椿，店里没有 | **能，且是唯一护城河** | 批次 2 |
| L2 | 理想的我 vs 晚上七点累坏的我 | **不能。任何内容都不能。别花时间** | — |
| L3 | 照片好看，我做出来不是那样 | 能，方法和所有人相反 | 批次 3 |
| L4 | 想吃老家那样，但我在西雅图 | **不要治，这是资产** | 批次 1 + 2 |

# 批次 1 · 零工程，纯文案（约 2 小时）

改字符串，不动结构。全部可以今天上线。

## 1.1 首屏主标题

**不要写**（这类都是加宽落差的写法）：
- 「顺应二十四节气，吃出健康生活」
- 「不时不食，遵循古人智慧」
- 「发现时令之美」

**改成**（承诺事实，不承诺意义）：

> # 这两周，买玉米
> 华盛顿州现在最便宜、最好的一样。
> 挑的时候扒开顶端看，粒要满到尖。

规则：**主标题必须是一个当下为真、两周后会变的具体事实。** 如果这句话一年到头都成立，它就是错的。

判断标准：把标题给一个累坏的人看，他应该知道**下一步该做什么**，而不是知道**他应该成为什么样的人**。

## 1.2 加一句宽容声明（关键，位置在首屏下方）

原文照抄：

> 错过了没关系。
> 一年有 24 个节气，两周后还有一次。

**为什么这句值 2 小时**：减肥破戒一次就"失败了"，节气没有失败态——这是这个品类结构上唯一的优势，目前没有任何产品在用。这句话把"我又没做到"变成"下次还有"。

## 1.3 地理落差直接说出来（`⚠️需确认` 站点是否已有地区概念）

在任何显示节气食材的地方，加一个固定区块：

> **老家这周吃的是**：莲藕、菱角、鸭子
> **你这边**：莲藕亚洲超市有，是进口的，不是当季；菱角基本买不到
> **别找了，换这个**：本地甜玉米和冬瓜现在正好，做法在下面

这一段的作用不是信息，是**把落差从"我的失败"变成"有人替我处理了"**。同一件事，从伤口变成服务。

## 1.4 作者身份，一句话，放页脚或关于页

> 我在华盛顿州，自己也在这些超市买菜。这份东西最早是我自己在用的。

**这是全站最有效的一句文案。** 它把作者从"过着你达不到的生活的人"变成"和你一样的人"。落差感的一大半来自前者。

## 1.5 立刻删掉的文案

| 删除对象 | 原因 |
|---|---|
| 任何功效说法：润肺、降火、排毒、增强免疫、去湿、养胃 | 法律风险（approval-policy H5），而且用户早就不信 |
| 「坚持」「打卡」「连续 N 天」 | 连续记录是落差放大器，断一次产品就变成指控 |
| 「全部 24 节气」这类大而全入口 | 它在展示你没完成的另外 23 个 |
| 「限时」「仅今日」等假紧迫 | 「过两周就没了」是真的，「限时优惠」不是。真的那个更有力 |
| 一切「打造」「开启」「探索」「之美」 | 这些词只出现在没有具体内容可写的时候 |

# 批次 2 · 核心功能（约半天）

## 2.1 把最小单位从「食谱」改成「这两周买一样」

**当前（推测）**：一个节气 → 一堆食材 → 一堆食谱。用户面对一个列表，做不出选择，关掉。

**改成**：首屏只有**一样东西**。

```
┌─────────────────────────────┐
│  处暑 · 8月23日 – 9月6日      │
│                             │
│  这两周，买玉米               │
│  [一张实拍图]                 │
│                             │
│  为什么现在  全年最便宜的两周   │
│  怎么挑     扒开顶端，粒满到尖 │
│  今晚做     玉米炒蛋 · 4 分钟  │
│                             │
│  [ 今晚就做这个 ]             │
│                             │
│  ─────────────────          │
│  还有 13 样 ▾  (默认折叠)      │
└─────────────────────────────┘
```

**设计约束（不要违反）：**
1. 首屏**只能有一个食材、一道菜**。第二个选择就是决策成本。
2. 那道菜必须 ≤ 15 分钟、≤ 5 样材料、不需要特殊调料。**首屏那道菜是给最累的那天准备的**，不是给周末准备的。
3. 「还有 13 样」默认折叠。想深入的人会点，累坏的人不用面对。
4. 不要进度条、不要完成勾选、不要「已解锁 3/14」。

**技术上**：如果现在是数据库驱动的列表页，这只是加一个 `featured: true` 字段和一个新的首屏组件。不需要重构。

## 2.2 替换表 —— 这是整个产品唯一不可复制的东西

**为什么它是护城河**：GPT 不知道这周 H Mart 货架上有什么。下厨房不知道 Trader Joe's 长什么样。国内节气号不知道西雅图。**只有一个既懂老家吃法、又真的在这边买过菜的人能做这张表。**

数据结构（起手可以是一个静态 JSON，不需要数据库）：

```
{
  "jieqi": "处暑",
  "date_range": "2026-08-23 to 2026-09-06",
  "region": "pacific-northwest",
  "substitutions": [
    {
      "homeland_item": "莲藕",
      "homeland_note": "处暑之后秋藕上市，煲汤用",
      "local_status": "partial",
      "local_note": "亚洲超市有，但是进口的，不是本地当季，价格和状态都一般",
      "substitute": "冬瓜",
      "substitute_why": "同样是煲汤的清甜底子，本地这两周最便宜",
      "recipe_adjustment": "冬瓜比藕出水多，汤水减三分之一，起锅前再放",
      "verify_at": "H Mart / 99 Ranch / Viet-Wah"
    },
    {
      "homeland_item": "菱角",
      "local_status": "unavailable",
      "local_note": "基本买不到鲜的",
      "substitute": "芋头 或 罐头荸荠",
      "substitute_why": "粉糯口感最接近；荸荠取脆",
      "recipe_adjustment": "芋头要先蒸再烧，不然吸油",
      "verify_at": "H Mart / 99 Ranch"
    }
  ],
  "local_only": [
    {
      "item": "甜玉米",
      "note": "老家这时候不算主角，这边是全年最好的两周",
      "chinese_dish": "玉米炒蛋 / 玉米排骨汤"
    },
    {
      "item": "意大利李子 Italian prune plum",
      "note": "老家没有这个品种，八月底刚上，farmers market",
      "chinese_dish": "糖水李子 / 配烤肉解腻"
    }
  ]
}
```

**三个字段是灵魂，别省：**
- `local_status`：`available` / `partial` / `unavailable` —— **诚实说买不到，比给一个买得到的假答案强十倍**
- `recipe_adjustment`：替代不是等价交换，做法要改什么必须写。不写这条，用户做砸一次就不回来了
- `verify_at`：说清楚在哪家店。这是你和 GPT 的全部区别

**⚠️ 起始表需要你去店里核实。** 我给的处暑条目是**起草**，不是观测——我没进过 H Mart。上线前你自己走一趟，对不上的直接改。这一趟是产品，不是调研。

## 2.3 「今晚就做这个」按钮的落点

点进去不是食谱页，是**一屏能读完的三步**：

```
玉米炒蛋

买    玉米 2 根 · 鸡蛋 3 个   （其他都是你家有的）
做    1. 玉米粒剥下来，鸡蛋打散加盐
      2. 热油炒蛋，八分熟盛出
      3. 玉米下锅炒 2 分钟，倒回鸡蛋，翻两下出锅
时间   4 分钟
```

**不要**：分步配图、营养成分、小贴士、评论区、相关推荐。这些都是给周末的人准备的，首屏这道菜是给周三晚上七点的人准备的。

# 批次 3 · 视觉（约一天，可外包给自己一个周末）

## 3.1 摄影规格 —— 具体到可执行

**目标不是"丑"，是"够得着"。** 判断标准只有一条：

> 用户看完第一反应是「**这我能做**」，不是「这好美」。

| 项目 | 要 | 不要 |
|---|---|---|
| 光 | 下午 4–6 点靠窗自然光；或者晚上就开厨房顶灯 | 补光灯、反光板、柔光箱 |
| 台面 | 你家真实的台面 | 大理石板、原木砧板道具、亚麻桌布 |
| 餐具 | 你家平时用的碗 | 粗陶、日式手作、成套餐具 |
| 构图 | 45 度角俯拍，画面里有别的东西（厨房纸、酱油瓶、灶台边缘） | 正俯拍纯色背景（那是杂志语言，不是家里） |
| 状态 | 切得不齐可以留、有水渍可以留、盛得不满可以留 | 摆盘、撒装饰香菜、擦干净每一滴 |
| 后期 | 亮度对比度微调 | 滤镜、调色、去杂物 |

**为什么这么反直觉**：完美的照片是在向用户承诺一个他家厨房兑现不了的结果。他做出来不像，落差就产生了，然后他不再打开。**小红书那套美学正是制造落差的机器。**

## 3.2 一个可以立刻做的测试

拍同一道玉米炒蛋两张：一张摆盘打光、一张你家灶台随手拍。放在两个链接下，看哪个的「今晚就做这个」点击率高。

我赌随手那张赢，但这是可以两天出结果的事，不用赌。

# 衡量：只看一个数

**唯一指标：买了第 N 期的人，会不会买第 N+1 期。**

不看喜欢、不看收藏、不看停留时长、不看「好治愈」的留言。这些全是加宽落差时也会涨的数字。

| 观察 | 结论 |
|---|---|
| 连续买两期 | 落差对他关上了。去问他为什么 |
| 买一期不买第二期 | **不是他懒，是第一期没兑现。** 去看他打开了哪几页 |
| 第二期买、第三期不买 | 内容重复度太高，替换表不够深 |

**节气每 15 天一次 —— 这是这个品类唯一的好处：复购信号两周就到，比任何品类都快。** 不需要等三个月。

# 明确不做的

- **不治 L2**（理想的我 vs 累坏的我）。任何内容产品都治不了一个人晚上七点不想做饭。能做的只是把门槛降到即使那天也跨得过去。
- 不做打卡、连续、成就、等级。
- 不做「全年节气日历」总览页。它的作用是展示你没完成的部分。
- 不做社区、评论、UGC。你现在没有用户密度，空评论区比没有评论区更伤。
- 不加功效说法。一条都不加。
